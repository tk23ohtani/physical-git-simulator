# 物理Gitゲーム

> 付箋はROM、ホワイトボードはポインタ、Content Matrix は検索台帳。

Git の内部構造（blob/tree/commit、branch/HEAD、コンテンツアドレッシング）を
「手で触れるゲーム」で体得するためのプロジェクト。

---

## コンセプト

- **不変追記 + 可変ポインタ + 内容アドレッシング** の3原則を身体で理解する
- 「Gitの使い方」ではなく「Gitの気持ち」がわかるゲーム
- 「嘘にならないレベルで、可能な限り人間に分かりやすく」が設計基準

---

## Content Matrix 方式

blob の中身を「形状-数字」の2ワードで表現し、4形状（○×△□）× 4数字（1-4）= 16マスの Content Matrix で管理する。

- **blob / tree / commit すべて連番**（B1, T1, C1...）で ID を振る
- blob の中身は「形状-数字」（例: ○-2）。blob 付箋には ID と中身を両方書く（例: B1 / ○-2）
- **Content Matrix は「中身 → Blob ID」の逆引き検索台帳**。tree を書くときにここで中身を探し、既存の Blob ID を見つけて使い回す
- tree には `HOGE.txt → B3` のように Blob ID で参照を書く
- 2ワード構成により conflict の可視化が可能（形状だけ変えた / 数字だけ変えた）

> 本物の Git では全オブジェクトがハッシュでアドレッシングされる。このゲームでは ID を連番で簡略化しつつ、Content Matrix による「同じ中身なら同じ blob を使い回す」体験でコンテンツアドレッサブルの本質を伝える。

### バージョン構想

- **v2.0: 分散リポジトリ編** — 机を2つ用意して fetch/push/pull を体験。「push できないあれ」の正体が見える。雲ではなく「同じ構造がもう1セットある」。force push = 相手の机の付箋を問答無用で差し替える暴力行為も体験
- **v3.0: staging 編** — ファイル付箋を導入し working directory / staging / repository の3層を体験。`git add` の意味が分かる（※ファイル付箋の物理的制約にブレークスルーが必要）

## 現実編（構想）: 禁止事項を破る操作群

初級の「禁止事項」を意図的に破る操作を体験する。なぜ禁止なのかが手間で分かる。

| Git操作 | 物理表現 |
|---|---|
| `stash` | 付箋をクリアファイルに挟んで脇に置く → 戻すときに出す |
| `rebase` | 付箋を新しく作り直して、古い方を裏返す（存在はするが参照されない） |
| `reset --soft` | ホワイトボードだけ巻き戻す。付箋はそのまま |
| `reset --hard` | ホワイトボードを巻き戻して、付箋を裏返す（見えなくする） |
| `reflog` | 裏返した付箋の一覧表（ホワイトボードの書き換え履歴） |
| `gc` | 誰からも参照されない裏返し付箋をゴミ箱へ |
| `cherry-pick` | 別ブランチの commit を見て「同じ変更内容」の付箋セットを今の位置に新規作成。parent が違うから commit ID は別物。blob は使い回せるが commit は必ず新規 |
| `commit --amend` | 新しい commit を作って参照を付け替える。古い commit は裏返し |
